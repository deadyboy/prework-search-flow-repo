# Case Evaluation Card

## Case ID

E1

## Case Type

Meta-framework

## Why This Case Exists

This case tests whether Prework Intelligence should learn from existing skill and agent workflow frameworks without copying execution-framework complexity too early.

## Must Discover

- Skill file structures, triggers, inputs, outputs, allowed behavior, prohibited behavior, verification, and resources.
- Agent/workflow primitives such as graph state, handoff, tools, guardrails, tracing, and memory.
- Whether any framework already provides the same Search Module -> Evidence Pack -> Judgment Module separation.

## Must Not Misjudge

- Do not treat an agent orchestration framework as an existing Prework Intelligence framework.
- Do not copy execution complexity before a case proves it is needed.
- Do not collapse Search and Judgment because other frameworks combine gathering, analysis, and action.

## Critical Distinctions

- claim_scope: skill packaging; workflow orchestration; guardrails; module separation; framework comparison.
- surface_scope: cross_surface.
- lifecycle_scope: not_applicable.
- freshness_scope: current_official; recent_but_unverified.
- privacy_scope: public framework docs only.

## Required Source Classes

- official docs: agent/skill framework docs.
- GitHub/open-source: official skill repos when relevant.
- product/community: framework comparison guidance.
- papers: not required.
- local/user-provided: not used.
- negative/failure search: no evidence of a ready-made Prework Intelligence equivalent.

## Minimum Acceptable Evidence Pack

- Identifies skill-format entities and agent-framework entities separately.
- Records reusable parts and non-reusable complexity.
- Includes negative evidence for a ready-made equivalent framework.
- Does not output Judgment conclusions.

## Minimum Acceptable Judgment Report

- Gives claim-level reuse decisions.
- Does not recommend agent automation as the immediate next step.
- Cites only Evidence Pack records.
