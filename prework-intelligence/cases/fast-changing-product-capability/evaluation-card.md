# Case Evaluation Card

## Case ID

A3

## Case Type

Calibration

## Why This Case Exists

This case tests the Current Product Capability Gate: older issues may record real historical gaps, but newer official changelog and docs can supersede them.

## Must Discover

- Official release or changelog evidence for the current capability.
- Current docs describing support and limits.
- Older issue evidence and its date relative to release evidence.
- Whether account, region, plan, or hands-on UI evidence remains unverified.

## Must Not Misjudge

- Do not let a stale issue override current official release evidence.
- Do not describe one surface or region limit as product-wide absence.
- Do not omit freshness status.

## Critical Distinctions

- claim_scope: historical issue; current official support; foreground limitation; user environment availability.
- surface_scope: desktop_app; remote_thread; cross_surface.
- lifecycle_scope: not_applicable.
- freshness_scope: current_official; stale_issue; current_observed missing.
- privacy_scope: no account or UI inspection.

## Required Source Classes

- official docs: Codex changelog and Computer Use docs.
- GitHub/open-source: historical issue.
- product/community: optional.
- papers: not applicable.
- local/user-provided: current hands-on UI only if user allows.
- negative/failure search: unsupported background/parallel Windows use and account-specific availability.

## Minimum Acceptable Evidence Pack

- Records a release timeline.
- Marks older issue evidence as stale or historical.
- Records current official docs and remaining user-environment gaps.
- Does not output Judgment conclusions.

## Minimum Acceptable Judgment Report

- Uses current official evidence before older issue evidence.
- Keeps limitations such as foreground control and account/region eligibility separate from capability existence.
- Cites only Evidence Pack records.
