核心规则
Search and Judgment are separate.

Workflow

主流程只有一个严格交接点：Evidence Pack。

Search -> Evidence Pack -> Judgment
1

Idea Card

记录原始想法、用户场景、输入输出、约束和不可接受替代。

Output: idea-card.md
2

Search Plan

规划 source class、query matrix、排除规则和停止规则。

Output: search-plan.md
3

Search Module

执行搜索并聚合实体。只记录证据、分数、缺口和负面搜索范围。

Output: evidence-pack.md
4

Judgment Module

只读取 Evidence Pack。不能搜索、不能新增实体、不能补证据。

Input only: evidence-pack.md
5

Judgment Report

每个结论必须引用 entity_id 或 negative_evidence_id。

Output: judgment-report.md
6

Retrospective

复盘字段、搜索源、评分稳定性和结论是否能指导行动。

Output: case-retrospective.md
Evidence Pack 是 Search 和 Judgment 之间唯一交接物。Search Plan 不是 Judgment 证据。

判断结论词汇

Judgment Report 只能从这些结论中选一个，并且必须引用 Evidence Pack 中的记录。

放弃不做

已有证据表明现在不值得继续。

直接采用

已有方案足够贴合，可以直接使用。

接入改造

已有方案覆盖基础需求，需要集成、包装或轻改。

场景定制

通用方案存在，但用户场景需要垂直化。

补齐缺口

已有基础，主要价值是补工作流、体验或最后一公里。A1 回归测试展示了这类判断。

自研小样

没有合适可复用基础，适合先做小型自研原型。

先补证据

证据包不足，不应强行判断。

语言分层

为了让中文读者更容易阅读，同时保持字段和接口稳定，文档按用途决定语言。

查看 language-guide.md

中文优先

状态、路线图、停止规则、案例复盘、判断理由和展示页。它们主要给人读。

中英混合

模板、Evidence Pack 和 Strategy Cards。说明用中文，字段名和 query templates 保持英文。

英文保留

文件名、字段名、枚举值、URL、repo 名、issue 标题和外部来源标题。
